# PadPilot 無頭開機修復與邏輯檢查

日期：2026-09-09（Asia/Taipei）

## 結論與證據

本機 `~/Library/Logs/PadPilot/padpilot.log` 在 00:00:54、00:00:57 與 00:01:27 均記錄：`Physical=['Generic Display']`、`USB_iPad=False`、`SidecarAvail=True`，決策為 `PHYSICAL`。這足以確認本次開機沒有進入 iPad 接管路徑。不能把此結果推廣成所有 Apple Silicon、所有 Generic 名稱或所有 vendor=0 都一定是假螢幕。

目前程式已有 USB 尚未就緒時使用配對 Sidecar 目標的路徑，因此修正精確的佔位名稱辨識後，該次紀錄對應的狀態會選擇 `IPAD_MAIN`。測試用相同輸入驗證從偵測、policy 到連線及設主螢幕的呼叫，同時驗證 ROG 仍優先。

## 已修正的衝突

| 原本的衝突 | 修正後 |
| --- | --- |
| Generic Display 被視為實體螢幕，提早結束暖機 | 精確排除 Generic／Generic Display；不廣泛排除所有 vendor=0 |
| 空白忽略項目或空白虛擬螢幕名稱會匹配全部螢幕 | 空白值不參與忽略匹配 |
| Prefer iPad、手動主／副螢幕繞過 Automatic 的冷卻 | 所有需要 Sidecar 連線的決策經共同冷卻檢查 |
| 手動斷線清除覆寫後，自動模式可能立刻連回 | 明確的 IPAD_DISCONNECTED 覆寫，在本次拓撲內禁止自動連回 |
| 主螢幕切換失敗仍移除虛擬備援 | 指令成功且重新觀察到正確主螢幕，才移除備援 |
| 實體螢幕接回時，虛擬主螢幕可能被當成副螢幕目標已滿足 | 主螢幕必須實際屬於實體螢幕清單；補齊切回實體的目標 |
| Sidecar 已連線但裝置發現清單暫時消失，改選虛擬螢幕 | 已連線狀態也保留 iPad 主螢幕決策 |
| 手動模式變更／重連和自動切換同時操作硬體 | 用同一狀態鎖依序處理；連線等待後重新核對拓撲再切主螢幕 |
| 切換結尾的觀察沒有更新拓撲世代及防抖 | 所有觀察路徑共用世代、覆寫失效與防抖更新 |
| IPC 逾時就刪除 socket 並誤報背景程式停止 | 保留 socket，回報指令結果未確認，避免錯誤自動重啟 |
| 任何 VirtualScreen 都被當成 PadPilotVirtual | 只承認設定的完整名稱，無有效 displayID 不當成已連線 |
| 探測失敗卻回報支援全部功能 | 執行檔可用與功能確認分開；啟動 BetterDisplay 後才探測 |
| 既有單元測試寫入真實設定／狀態或觸發選單刷新 | 隔離測試設定保存、狀態輸出與系統互動 |

修正使用 Python 標準函式庫及現有測試工具，沒有新增依賴。

## 仍需注意的範圍

1. Generic 名稱仍是這台機器觀察到的辨識捷徑。若另一台真實螢幕也只叫 Generic Display，需取得 EDID／registry 資料做進一步辨識；本次未宣稱跨所有機型通用。
2. 目前硬體變更靠開機暖機與 30 秒輪詢，沒有原生睡眠／喚醒事件監聽。4 秒防抖不是保證 4 秒內完成切換；README 已校正。
3. 狀態操作採序列化，慢速 Sidecar 指令可能讓手動命令暫時等待；IPC 逾時不代表命令取消。多 iPad 同時在線與異常設定檔／跨使用者暫存目錄情境尚未全面驗收。
4. `autostart` 目前以 plist 是否存在顯示啟用狀態，載入失敗也可能只記錄警告；這次實機已直接核對 launchd 的執行狀態，但沒有重做整套啟停管理。

## 冷開機驗收

1. 保持 Automatic，確認 iPad 可使用且可被 Sidecar 發現；拔除實體螢幕傳輸線再重開 Mac。
2. 預期登入後接管 iPad，日誌應出現 `Physical=[]` 與 `Desired=IPAD_MAIN`，而非 Generic Display 的 PHYSICAL 判斷。
3. 確認 iPad 顯示畫面且為主螢幕；再接回 ROG，確認自動模式回到實體優先。
4. 若失敗，保留從 `Daemon starting up` 起的日誌與當時 status.json；檢查是目標不可用、連線失敗、設主螢幕失敗或偵測分類，不以手動成功取代冷開機證據。


## 後續冷開機驗證：保留虛擬備援

01:14:41 與 01:15:01 的紀錄顯示，移除虛擬備援與 Sidecar 中止發生在同一秒；但 01:14:26 首次中止更早，尚不能確認移除備援是唯一原因。

本次改為：無頭連線前接上已配置的 PadPilotVirtual，切換到 iPad 主螢幕後不再自動移除虛擬備援。這取代上表「觀察到正確主螢幕後移除備援」的行為。虛擬備援會留作額外顯示器；沒有變更 iPad 鎖定設定、重試或冷卻策略。是否排除冷開機反覆退出，仍需實機驗證。
