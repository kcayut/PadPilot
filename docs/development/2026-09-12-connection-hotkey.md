# 全域連線快速鍵

本輪加入原生選單列快速鍵，由直接連到 Mac 的鍵盤提出連線要求。設定沿用 GUI → CLI → IPC → daemon 交易與版本檢查，實際連線仍交由既有狀態機。使用 macOS 原生註冊，未新增套件或鍵盤監聽器。

- 自動模式維持既有自動連線；快速鍵另提出一輪要求。
- 僅手動模式中的快捷鍵與主／副螢幕選單要求只維持一輪，結束後移除要求，保留成功建立的連線。後續斷線、USB 事件與裝置重新出現都不自行重連。
- 一輪沿用既有重試設定，預設最多 3 次；長按與進行中的重複要求合併，不增加重試額度。已連線且畫面上線時不重新斷接或改變主／副螢幕角色。
- 設定修改不掃描硬體、不重設重試保護。快捷鍵不重啟已停止的背景服務，以免服務啟動自動連線與明確要求各執行一輪。
- 初次停用，設定頁預填 ⌃⌥⌘I，儲存後生效；可更換字母／數字及修飾鍵或停用。至少需要 Control 或 Command，註冊衝突以非模態提示處理。

## 驗證結果

- 完整單元測試：225 項通過，無 ResourceWarning。包含原生快捷鍵實際註冊、衝突、按下／放開事件、長按抑制與取消註冊。
- 連線以模擬硬體測試成功／失敗、進行中的重複要求、既有連線不重建，以及手動模式在 25 小時的 USB／Sidecar 狀態變動後仍不自行連線。
- 繁中、英文、日文設定頁以獨立原生測試視窗實際擷取、目視檢查；儲存動作經共用 CLI，且不發出硬體掃描。測試未修改實際快速鍵或 iPad 設定。
- `check_release.py --gui`：單元測試、安裝腳本語法、LaunchAgent、版本與差異格式通過；隱私掃描為 `tree=0, history=0, accepted_history=6`。
- 原有版面與三語自動檢查未通過，皆停於配對頁的 `Missing native disclosure: paired`。以修改前的設定視窗與檢查原始碼重現同一失敗；本輪未放寬斷言，也未將畫面檢視當作完整自動版面檢查通過。
- 本機 App 已經由既有安裝流程更新，背景服務重新載入；安裝後執行檔與本輪建置一致，原設定檔內容逐位元組相同，快速鍵保持初始停用。

## 驗證邊界

未實測實體鍵盤經快捷鍵啟動 USB／無線 Sidecar、無實體螢幕或 iPad 鎖定等組合。Mac 必須已登入，選單列程式與背景服務必須執行。快捷鍵代表使用者提出要求，不代表已證實 iPad 能連線；Sidecar 自行產生的黃色系統警告仍不保證消失。

自動版面檢查與實體驗收尚未全部通過，因此本紀錄不代表穩定版發布驗收完成。

## 後續：快速鍵失敗通知補充原因

使用者回報按鍵後只看到 `PadPilot Operation Failed`。當時的實際紀錄顯示 Sidecar 清單沒有選定的 iPad，連線狀態查詢回覆 `Failed.`。狀態機在送出連線指令之前拒絕要求；該回覆無法證明 iPad 是鎖定、休眠或其他原因。

原本有三處丟失資訊：狀態機把查詢錯誤改成籠統字串、daemon 回傳固定錯誤、原生程式忽略 CLI 的錯誤內容。另外 CLI 與原生程式各發一則通知。

後續修正保留失敗的查詢項目與原始回覆，區分找不到選定的 iPad、未設定目標、服務停止與回應逾時。訊息經 CLI 翻譯後直接交給原生通知；快速鍵的 CLI 路徑只回傳錯誤，不另發重複通知。其他連線規則與裝置判斷維持不變。

範例：目前 Sidecar 裝置清單沒有選定的 iPad（BetterDisplay 狀態查詢回覆：Failed.）；尚未發起連線。

完整測試 226 項通過；針對六類查詢錯誤、原始回覆、缺少目標及三語 CLI 錯誤的測試，確認失敗時不連線、CLI 不另發通知。上述既有自動版面與實體驗收限制仍適用。
