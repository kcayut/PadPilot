## 結論と証拠

`~/Library/Logs/PadPilot/padpilot.log` の 00:00:54、00:00:57、00:01:27 に `Physical=['Generic Display']`、`USB_iPad=False`、`SidecarAvail=True` と `PHYSICAL` 判定が記録されました。この起動で iPad への切り替え経路に入らなかったことを示します。すべての Apple Silicon、Generic 名、vendor=0 の画面が仮の画面だという証明ではありません。

USB の準備前でもペアリング済み Sidecar 対象を使う経路は既に存在しました。既知の仮画面名を正しく分類すると、この入力では `IPAD_MAIN` が選ばれます。検出 → 方針判断 → 接続・メイン設定を同じ入力で検証し、ROG 物理モニターが引き続き優先されることも確認しました。

## 当時の残存制限

1. Generic 名による識別はこの機体の観測に基づきます。同名の実モニターは EDID/registry 情報による調査が必要で、全機種で正しいとはしていません。
2. 構成変更は起動探索と 30 秒ポーリングで確認し、ネイティブのスリープ・復帰監視はありませんでした。4 秒の待機は 4 秒以内の完了保証ではなく、README を修正しました。
3. Sidecar 処理が遅いと直列化された手動操作も待機します。IPC タイムアウトはキャンセルではありません。複数 iPad、異常設定、他ユーザーの一時パスは網羅的に未検証でした。
4. 当時の `autostart` は plist の存在で有効状態を判定し、読み込み失敗を警告だけにする場合がありました。実行中の launchd は直接確認しましたが、この修正で起動管理全体は作り直していません。

## コールドブートの受け入れ手順

1. Automatic と Sidecar で見つかる iPad を準備し、物理モニターを外して Mac を再起動します。
2. ログイン後、`Physical=[]` と `Desired=IPAD_MAIN` を期待します。Generic Display による `PHYSICAL` 判定ではないことを確認します。
3. iPad の実表示とメイン設定を確認し、ROG を接続して自動モードが物理優先へ戻るか確認します。
4. 失敗時は `Daemon starting up` からのログと status.json を保存します。対象不在、接続失敗、メイン変更失敗、分類誤りを区別し、手動成功をコールドブートの証拠に代用しません。

## 後続修正：仮想画面の保持

01:14:41 と 01:15:01 は、仮想画面削除と Sidecar 終了が同じ秒に発生しました。ただし最初の終了は 01:14:26 で、それより早いため、削除だけが原因とは確認できません。

後続修正では接続前に PadPilotVirtual を接続し、iPad がメインになった後も残します。上表の「確認後に削除」を置き換える方針です。仮想画面は追加画面として残り、iPad のロック設定、再試行、クールダウンは変更していません。コールドブート時の繰り返し終了が解消するかは実機検証が必要です。
