# iPad 離線後反覆重連與警告累積

## 問題與根因

2026-09-12 本機日誌在 09:00 至 09:20 反覆記錄：無實體螢幕、USB iPad 不在、Sidecar 清單仍有目標、主螢幕手動覆寫仍有效。每輪失敗 3 次後通知、冷卻 30 秒，再開新一輪。原有上限只限制單輪，無法防止長時間離線時持續發出 Sidecar 連線要求與通知。

USB 通知只喚醒既有評估器；自動偵測沿用明確配對。問題在所有入口共用的重試生命週期，不需要另建 USB 控制流程。未擷取當時警告視窗，無法逐一判定系統對話框與 PadPilot 通知的來源。

## 修復

- 保留耗盡的重試計數；冷卻到期、備援已就緒、一般 USB 喚醒、重新整理與實體螢幕變動均不再清除它。
- 每輪最多依設定嘗試（預設 3 次），耗盡通知一次，停止自動 Sidecar 重試並保留備援；自動、偏好 iPad 與既有主／副螢幕覆寫共用此保護。
- 只有有效觀測確認目標 USB／Sidecar 可用狀態由無變有，才重新允許有限次數的重試，仍遵守剩餘冷卻。查詢錯誤不會偽造拔除／重新出現。
- 已確認 session 與顯示器皆上線，或使用者手動選擇主／副螢幕、重新連線、重設，可恢復操作。若只是點亮 iPad 而沒有新的偵測變化，使用「重新連線」。重試計數仍是程序內的暫時狀態，重啟服務會重新開始計數。
- 更新三語狀態文字與使用者文件。

## 驗證與載入

- 新增 5 項回歸，含無頭、兩個選項皆開啟、USB 留著／不在、24 小時時間推進、通知次數、查詢錯誤、USB／Sidecar 重新出現、備援切換、手動控制與延後上線。原始碼修改前，長時間離線案例的連線呼叫為 78 次，預期為 3 次；修改後通過。
- `python3 -m unittest discover -s tests` 執行 218 項；216 項在沙箱內通過。通訊端權限與原生視窗啟動兩項受沙箱限制，於沙箱外重跑均通過。相關狀態機、USB、控制與三語測試 80 項通過；`git diff --check` 通過。
- 已核對既有 LaunchAgent 執行目前 checkout，並重啟載入修復。新程序狀態正常，BenQ GW2406Z 仍為主螢幕，虛擬備援維持連線，無查詢錯誤或執行錯誤；設定檔 SHA-256 前後相同。
- 載入時使用者目前的兩個選項均為關閉，未自動修改。選項開啟的離線情境已由回歸測試涵蓋；尚未進行關閉真實 iPad 並拔除實體螢幕、長時間放置的實機驗收。
