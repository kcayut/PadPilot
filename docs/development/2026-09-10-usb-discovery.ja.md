# USB 通知と未ペアリング iPad の自動検出

[繁體中文](2026-09-10-usb-discovery.md) | [English](2026-09-10-usb-discovery.en.md) | **日本語** · [開発記録一覧](README.ja.md)

> 過去の記録です。下表は初版の既定値と動作です。現在は自動検出が既定で有効で、明示的なペアリングを優先します。[現在の設計](../ARCHITECTURE.ja.md)を参照してください。

USB と iPad 自動検出の設定カードを追加し、既存の GUI → CLI → IPC → 設定トランザクションと状態機械を使用しました。

| スイッチ | 初版の既定値 | 動作 |
| --- | --- | --- |
| USB イベント通知 | 有効 | IOKit first-match/terminated コールバックで既存評価ループを起動。探索、デバウンス、クールダウン、watchdog は維持。 |
| iPad 自動検出 | 無効 | USB iPad が 1 台であることを確認し、保存済み対応を優先。なければ Sidecar 候補も 1 台であることを要求。対象は観測状態だけに保存。 |

メニューに今回の対象を表示します。初版では、自動検出中の保存済みペアリング操作を無効にし、古いラベルで別の機器を操作することを防ぎました。設定変更は共通評価ロックの解放後に適用します。外部パッケージは追加していません。

## 検証

- `python3 -m unittest discover -s tests`：115 テスト成功、うち新規 11 件。設定検証、CLI/IPC、通知登録・停止・再起動、登録失敗時の watchdog 継続、既存ループの起動、単一未ペアリング候補、保存済み対応優先、曖昧・照会失敗時の接続抑止、対象変更、メイン操作、手動モード、クールダウンを検証。
- `python3 scripts/check_gui_layout.py`：幅 840px で成功。両スイッチが表示され、正しい設定を送信し、自動検出時のペアリング操作が無効であることを確認。
- `git diff --check`：成功。
- ローカル IOKit の登録、停止、再起動が成功。08:23 に既存 LaunchAgent を再起動後、`Native USB notifications active` を確認し、状態に `resolved_ipad` があり、検出エラーはありませんでした。
- ユーザーの手動モード、ペアリング、ROG PG279Q のメイン設定を保持し、未ペアリング自動接続は有効にしていません。

## 制限

USB と Sidecar の候補がそれぞれ 1 台でも、同一機器である証明ではありません。複数 iPad 環境では明示的にペアリングしてください。Apple Account、信頼、Sidecar 対応条件は変わりません。

実際の抜き差し、別の未ペアリング iPad への交換、物理モニターなしのコールドブートは実施していません。これらの受け入れ完了やミリ秒単位での Sidecar 接続完了は主張しません。自動接続には自動モードまたは iPad 優先モードの選択も必要です。
